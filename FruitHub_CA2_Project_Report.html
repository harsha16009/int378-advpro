Abstract

The FruitHub Platform is a cloud-native, microservices-driven e-commerce grocery and fresh fruit ordering application. It allows customers to browse fresh produce catalogues, manage shopping carts, execute secure UPI/QR and mock payments, receive real-time delivery tracking with interactive mapping, and engage in real-time customer support chat. Administrators can manage inventory catalogues, track global orders, and inspect delivery statuses through an interactive dashboard.

The frontend is built using React.js (Vite), Tailwind CSS, and Socket.io Client, while the backend is decoupled into eight specialized microservices: API Gateway, Authentication Service, Product Service, Order Service, Payment Service, Notification Service, Tracking Service, and Chat Service. Persistence is managed via MongoDB with isolated database domains.

This report focuses on the comprehensive DevOps engineering lifecycle designed around the platform: Docker container packaging, multi-container Docker Compose orchestration with isolated internal bridge networks, Kubernetes deployment with Kustomize manifests, infrastructure as code via Terraform for AWS ECS provisioning, automated continuous integration & deployment pipelines on Jenkins with GitHub webhooks, and full observability using Prometheus metrics scraping, Blackbox exporter probing, and Grafana performance dashboards.

1. Introduction

1.1 Background

Online grocery and fresh fruit delivery requires instant catalog discovery, resilient checkout and transaction flows, real-time dispatch updates, and responsive customer interaction. Traditional monolithic web applications suffer from single points of failure: a surge in checkout or tracking traffic can degrade the entire application. FruitHub addresses these scaling challenges by refactoring the domain into independent, loosely coupled microservices managed through modern containerization and orchestration tooling.

1.2 Project Objectives

  • Architect a resilient, multi-service e-commerce application with segregated responsibilities.
  • Standardize service builds using containerization (Docker) and multi-container coordination (Docker Compose).
  • Deploy declarative manifests across Kubernetes (Minikube) with rolling update capabilities and health checks.
  • Automate container build and deployment lifecycles using Jenkins CI/CD connected via GitHub Webhooks.
  • Provide comprehensive operational observability via Prometheus scraping, Blackbox probing, and Grafana visualization.
  • Define scalable cloud infrastructure using Terraform modules targeting AWS ECS.

8. Kubernetes (Minikube) Deployment & Orchestration

The application is packaged for Kubernetes using declarative YAML manifests structured under k8s/ and aggregated via k8s/kustomization.yaml.

8.1 Cluster Topology

  • Persistent Volume Claims: mongo-pvc allocates 2Gi storage mounted at /data/db for data preservation.
  • ClusterIP Services: Internal microservices (auth, product, order, payment, notification, tracking, chat) communicate over internal DNS.
  • NodePort Services: Exposed external entry points:
    • frontend: NodePort 31730
    • api-gateway: NodePort 30000
    • prometheus: NodePort 30090
    • grafana: NodePort 30300
  • Health & Readiness Probes: Each deployment configures livenessProbe and readinessProbe pointing to /health to ensure traffic is routed only to healthy containers.
# Sample Deployment Snippet (api-gateway.yaml)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-gateway
spec:
  replicas: 1
  template:
    spec:
      containers:
      - name: api-gateway
        image: fruithub-api-gateway:latest
        imagePullPolicy: IfNotPresent
        ports:
        - containerPort: 3000
        livenessProbe:
          httpGet:
            path: /health
            port: 3000
          initialDelaySeconds: 15

9. Infrastructure as Code (Terraform for AWS ECS)

The cloud infrastructure is provisioned through modular Terraform configurations located in terraform/, targeting AWS ECS in the ap-south-1 (Mumbai) region:

  • VPC Module: Custom 10.0.0.0/16 VPC with 2 public subnets and 2 private subnets across multiple availability zones.
  • Compute Module: AWS ECS Cluster (fruithub-cluster-dev) with task definitions for all 8 microservices and an Application Load Balancer.
  • Security Module: Restrictive Security Groups isolating backend microservices inside private subnets, permitting external ingress only on ports 80/443.

10. Continuous Integration & Deployment (Jenkins Pipeline)

The automated CI/CD pipeline is implemented in the repository's Jenkinsfile and executed within the local Jenkins container on port 8081. Webhook automation is enabled using ngrok to tunnel external GitHub push notifications directly to Jenkins. 

pipeline {
    agent any
    stages {
        stage('Clone Repository') {
            steps { checkout scm }
        }
        stage('Stop Old Containers') {
            steps {
                sh 'docker compose down || true'
                sh 'docker compose -p demo-micro down || true'
            }
        }
        stage('Build Containers') {
            steps { sh 'docker compose build' }
        }
        stage('Run Containers') {
            steps { sh 'docker compose up -d' }
        }
        stage('Check Running Containers') {
            steps { sh 'docker ps' }
        }
    }
}
